# 閲覧計測の安定化（2026-09-11）

## 数え方

- 累計ユニークは保存済みの匿名ブラウザーIDのSHA-256。既存のIDを継続使用する。同じ人の複数端末・ブラウザーは区別できない概算。
- 日次回数はアプリまたは公開記事の初回表示、非表示からの再表示、BFCacheからの復帰ごとに1回。SPA内の画面移動、フォーカスだけの移動、通信再試行では増やさない。
- サーバーに記録された日時を日本時間で日次集計する。既存RPCは元の発生日時を受け取らないため、オフライン記録の翌日配送は翌日の件数に入る。
- 運営者として確認済みのブラウザーはログアウト後も除外する。別端末では一度運営者ログインが必要。過去の記録を推測で削除・補正しない。

## 実装

- アプリと公開記事で assets/visitor-tracker.js を共用。Supabase SDKやニュース読み込みから独立して起動する。
- 表示ごとにUUIDを発行しlocalStorageへ保存。成功応答まで削除しない。再送・複数タブで同じUUIDを送っても、既存RPCの主キー制約により二重挿入しない。
- 8秒で応答待ちを打ち切り、4秒から最大60秒間隔で再送。再表示・通信復旧時にも送信。ユニークと日次は別々に処理する。
- ストレージが利用できない場合、日次はメモリー内で再送するが、タブを閉じると未送信分は失われ得る。ユニークは新規IDを毎回増やさない。
- 有効な旧会員セッションは権限を確認してから記録。確認済み管理者は除外、一般読者や期限切れの旧会員セッションを一律除外しない。
- 管理者統計は毎分・復帰時に取得。取得待ちを8秒で打ち切って再試行する。最後の成功値と時刻を同一アカウント向けに保存し、取得失敗を0として扱わない。
- 前日の回数を当日の値として再表示しない。公開利用者には統計を表示しない。サーバー側の管理者権限検査は維持する。

## 検証

node scripts/test-free-access-daily-metrics.mjs に、共通計測の動作試験と統計取得の動作試験を統合。既存の定期更新でも自動実行する。

PWA再表示・BFCache・重複イベント・保存済み再送・応答消失・本文タイムアウト・旧会員・管理者除外・ストレージ拒否・日本時間の日付変更・キャッシュ復元・アカウント切替・取得失敗を試験。

本番RPCの存在と匿名からの統計取得拒否は、記録を追加しない無効入力で確認済み。実際の管理者用件数は、ログイン済み管理者画面での確認が別途必要。記録されなかった過去の閲覧を復元したものではない。
