# 流入元の判別と計測リンクの改善

## 原因と限界

新規／再訪は匿名ブラウザーの利用履歴、流入元は URL の utm_source またはブラウザーの参照元で判定する。新規だから SNS 経由と推測することはできない。

現行の direct_unknown には、参照元がない初回表示と、ホーム画面からの起動・アプリ復帰が含まれる。これらの内訳は保存しておらず、過去分は復元できない。履歴の集計値は公開リポジトリーに記載しない。

初期ルーティングは URL の query を保持し、サービスワーカーもページ遷移時に query を削除していない。計測リンクを付けた、参照元なしの初回表示は既存トラッカーで判別できる。今回トラッカー・データベース・権限・カウンターの値は変更しない。

## 変更

- 管理画面の上部で「外部の流入元を判別できた」「流入元を判別できない」を分け、新規とは別の指標であることを説明。
- 「SNS別の計測リンクをコピー」を上部へ移動。X、YouTube、Instagram、note、Facebook の5種類を用意。
- 既存の外部プロフィール／投稿の通常 URL も置き換えが必要だと明記。今回、SNS上の投稿やプロフィールは変更していない。
- タグが削除された場合は判別できない。転載先が変わっても元のタグで集計する限界も明記。
- 復帰を元の SNS への流入として数え直さない。特定できないアクセスを隠す、任意の SNS へ割り当てる等は行わない。
- 更新済み画面を配信するサービスワーカーのキャッシュ番号を v40 へ更新。

## 検証

- 管理画面の private mount、期間変更、通信失敗、権限喪失、CSV、コピー機能のテスト。
- 全5種類の計測リンクを、参照元なしで開いた場合の分類をローカルの模擬ブラウザーで検証。
- 未知のタグは参照元で判定、参照元もない場合は判別不可のままとなることを確認。
- 同じブラウザーの復帰は元の SNS の流入を増やさない。運営者除外・再送の二重計上防止も維持。
- 本番へ架空アクセスを送信しない。
