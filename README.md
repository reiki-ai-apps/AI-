# AI進化レーダー（毎日自動更新版）

AIに関する重要ニュースを **朝・昼・夜の1日3回にまとめて審査** するダッシュボードです。

## 仕組み（むずかしくないので安心してください）

1. GitHub が **日本時間7:17・13:17・19:17** に `update.js` を自動実行
2. `update.js` がAIニュースを収集し、AIで日本語要約・重要度・分野を判定して `data.json` を更新
3. GitHub Pages が変更を検知して **サイトを自動で再公開**
4. アプリ（`index.html`）は開くたびに `data.json` を読むので、いつ開いても最新

→ 一度セットアップすれば、あとは **何も操作しなくても毎日勝手に更新** されます。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（これがサイトとして表示される） |
| `data.json` | 公開する要約済み最新ニュース（最大60件） |
| `update.js` | ニュースを集めて data.json を作るスクリプト（GitHubが実行） |
| `.ai-cache.json` | 同じ記事をAIで何度も処理しないための履歴（自動生成） |
| `.ai-usage.json` | 日別のAPI呼出数・トークン数・処理件数（自動生成） |
| `.story-index.json` | 同じ話題の前回記事と続報をつなぐ最小履歴（365日、自動生成） |
| `.github/workflows/update.yml` | 1日3回の監視・トップ5審査・公開設定 |

## セットアップ手順

詳しい手順は、チャットでClaudeが案内します。大まかには：

1. GitHub（無料）にこのフォルダ一式をアップロードして公開リポジトリにする
2. GitHub の **Settings → Pages** で GitHub Pages を有効にする
3. GitHub の **Actions** タブで `Update AI feeds` を一度手動実行（Run workflow）
4. 完了。以後は朝・昼・夜の1日3回、自動で確認・更新・公開されます

## AI利用量の安全設定

- 1回の実行は最大12記事です。政策・安全性・中国/世界の新モデル・半導体を先に1件ずつ確保します。
- 通常は1日40記事まで、重要分野のみ追加8記事まで処理できます。
- 採用済みは31日、不採用は7日記録し、同じ内容への重複課金を防ぎます。
- `.ai-usage.json` とGitHub ActionsのSummaryで、実際の入力・出力トークン数を確認できます。
- 金額換算を使う場合は、GitHub Actions Variablesに利用モデルの最新単価を設定します。単価未設定時は推測金額を表示せず、実トークン数だけを記録します。

## 記事の日付と続報

- カードは、出来事の日が確認できた記事だけ「出来事の日」を表示し、未確認の記事は「情報元の掲載日」だけを表示します。
- 詳細画面では、出来事の日が本文から確認できない場合も、取得日時などで補わず「記事内で確認できませんでした」と正直に表示します。
- 情報元に掲載日時がない場合も、推測の日付は表示しません。更新日時だけ確認できる場合は別項目として扱います。
- 過去365日以内の同じ話題に新しい動きがあった場合は「続報」として前回タイトル・掲載日・今回の新情報を表示します。
- 同じ企業の別発表や、数字が異なる別案件は自動で続報・重複扱いにしません。
- 前回の要約をアプリ内で開く操作では、情報元記事の月間閲覧枠を消費しません。

## 公開時の確認

- `index.html`、画像、マニフェストなどアプリシェルを変更したときは、`sw.js` の `CACHE_NAME` も更新します。
- 公開前に `node scripts/test-ai-operations.mjs`、`node scripts/test-dedupe.mjs`、`node scripts/security-check.mjs` を実行します。
- 一般利用者向けの登録・ログインはありません。Supabase認証は、運営者本人が匿名の利用状況を確認する場合にだけ使用します。
- 情報元記事の月間上限は、ブラウザから送る数字ではなく、Supabase内の契約プランからRPCが決定します。

## 取得対象を増やす・変える

`update.js` の先頭の `TOOLS` リストに、ツール名とフィードURLを足すだけです。
迷ったら Claude に「このツールを追加して」と頼んでください。
## 起動時の安定性

Service Workerの更新では表示中の画面を強制再読込しません。記事取得はJSON本文の受信まで8秒で区切り、失敗時は同じ画面で1秒・3秒・10秒後に最大3回再試行します。成功時だけ取得済みとし、通信復帰時にも再確認します。前回の記事・既読・保存・メモは維持します。`node scripts/test-runtime-resilience.mjs` は初回通信失敗、本文停止、再試行上限、同時取得、旧データ移行、キャッシュ引継ぎの実行テストを含みます。

## 専門家動画の更新時刻

ホームの動画記事は最大1件です。複数候補があっても既存の並び順で先頭の1件だけを表示し、他の動画は削除せず分類ページに残します。記事トップ5と動画の収集・保存件数には影響しません。

専門家動画は毎朝7:17（日本時間）の定期処理で1日1回選定します。公開は収集・審査完了後となり、GitHub Actionsの混雑で開始が遅れる場合があります。対象は元の投稿日が確認できる投稿後10日以内の動画です。昼・夜の定期処理や深夜の手動更新では新規選定しません。朝の処理が失敗した場合は朝7:17〜正午に手動再実行でき、未完了なら翌朝にも再試行します。


## 別サイト: 三高産業 ハウスEC(プロトタイプ)

`mitaka-ec/` フォルダは、ビニールハウス資材・施工のオンライン見積サイトの試作版です(このAIニュースサイトとは独立しています)。
3Dハウスシミュレーターで間口・奥行・設備を選ぶと、3Dモデルと概算見積りがその場で表示されます。
担当者コンソール(`mitaka-ec/staff.html`)には、今日やること・電話メモ・お客様の記録・災害モードが入っています。
GitHub Pages では `/mitaka-ec/` 配下でそのまま公開されます。詳細は `mitaka-ec/README.md` を参照してください。
